# STT Providers for a Real-Time German-Language Voice-Conversation AI Tutor (2026)

## What is the current official pricing (per minute/hour) for Deepgram, Soniox, AssemblyAI, OpenAI, Google Cloud STT, Azure Speech, Amazon Transcribe (and Gemini as a possible STT substitute)?

### Takeaway
All seven mainstream providers publish usage-based, pay-as-you-go pricing for real-time/streaming transcription, ranging from roughly $0.0048/min (Deepgram Nova-3 streaming, promo PAYG rate) up to $1/hour (~$0.0167/min) for Azure's standard real-time tier — a >20x spread. OpenAI and Gemini price transcription primarily as an LLM (token-based), with blended per-minute equivalents published by third parties, not as a native "per-minute STT" line item on OpenAI's own pricing page.

### Cited Findings
- **Deepgram** — Nova-3 Monolingual streaming: $0.0048/min pay-as-you-go (promotional rate; regular list rate $0.0077/min), $0.0042/min on the Growth plan (prepaid $4,000+/yr, ~20% off). Nova-3 Multilingual streaming: $0.0058/min PAYG (regular $0.0092/min), $0.0050/min Growth. Billed per-second. Voice Agent API (bundled STT+turn logic) is ~10x base rate at $0.08/min. — [Deepgram Pricing](https://deepgram.com/pricing) (fetched official page, Sept 2026)
- **Soniox** — Speech-to-Text: $0.10/hour async (file), $0.12/hour real-time streaming. No extra charge for diarization, language ID, or formatting; translation/custom-context features are billed separately by token. — [Soniox Pricing](https://soniox.com/pricing) (official page, Sept 2026)
- **AssemblyAI** — Universal-Streaming (English) and Universal-Streaming Multilingual (incl. German): $0.15/hr base. Universal-3.5 Pro Realtime: $0.45/hr. Streaming speaker diarization add-on: +$0.12/hr. Medical Mode (EN/ES/DE/FR): +$0.15/hr. Billing is by WebSocket session duration (including idle time), not audio duration — a real operational cost trap. Free tier: 333 streaming hours. — [AssemblyAI Pricing](https://www.assemblyai.com/pricing) (official page, Sept 2026); streaming rate corroborated by [AssemblyAI blog](https://www.assemblyai.com/blog/speech-recognition-cost)
- **OpenAI** — `whisper-1`: $0.006/min. `gpt-4o-transcribe`: $0.006/min equivalent (token pricing: $2.50/1M input tokens, $10/1M output tokens). `gpt-4o-mini-transcribe`: $0.003/min equivalent (token pricing: $1.25/1M input, $5/1M output). These are batch/one-shot transcription endpoints, not a persistent bidirectional streaming session (see next question). — [OpenAI API Pricing](https://developers.openai.com/api/docs/pricing) (official page, Sept 2026)
- **Google Cloud Speech-to-Text** — Standard V2 recognition: ~$0.016/min; V2 "dynamic batch" (delay-tolerant): ~$0.003/min. New customers get $300 credit + 60 free minutes/month. **Caveat**: I could not get Google's own pricing page to render in full (content was truncated on fetch); these figures are corroborated across multiple third-party aggregators (costbench.com, diyai.io) but not independently confirmed against the live official table in this session — treat as likely-correct but unverified-first-hand. — [Google Cloud Speech-to-Text Pricing](https://cloud.google.com/speech-to-text/pricing) (official URL, fetch truncated); secondary corroboration: [costbench.com](https://costbench.com/software/ai-transcription-apis/google-speech-to-text/)
- **Azure AI Speech** — Real-time standard transcription: ~$1.00/hour (~$0.0167/min); "fast transcription" mode: ~$0.36/hour but this is confirmed to be a **batch/near-real-time mode, not true streaming** (Azure's own docs describe it as requiring the Speech-to-text REST API's fast-transcription endpoint, separate from the real-time WebSocket path). Diarization add-on for real-time: +$0.30/hr. Committing to 50,000 hrs/year drops standard rate to ~$0.50/hr. Free tier: 5 hours/month. **Caveat**: Azure's own pricing page renders region-specific prices via JavaScript and returned masked "$-" placeholders on direct fetch in this session; the $1/hr and $0.36/hr figures come from third-party aggregators, not a first-hand read of the rendered official table. — [Azure Speech Pricing](https://azure.microsoft.com/en-us/pricing/details/speech/) (official URL, values not rendered on fetch); secondary: [brasstranscripts.com](https://brasstranscripts.com/blog/azure-speech-services-pricing-2025-microsoft-ecosystem-costs)
- **Amazon Transcribe** — Streaming (real-time): **$0.01/minute**, confirmed directly from AWS's own pricing page (US East N. Virginia example). Batch: $0.006/minute. Streaming is ~67% more expensive than batch per AWS's own comparison. Minimum billing increment is per-second with a 15-second minimum per request. — [Amazon Transcribe Pricing](https://aws.amazon.com/transcribe/pricing/) (official page, fetched directly, Sept 2026). Note: one third-party aggregator (brasstranscripts.com) separately quoted "$0.0004/sec ($1.44/hr)" for streaming, which conflicts with AWS's own $0.01/min ($0.60/hr) figure — I trust the official AWS page fetched directly over the conflicting aggregator number.
- **Gemini (Google DeepMind) as STT** — Gemini Live API (native audio, bidirectional): $0.005/min audio input, $0.018/min audio output (token-based, priced as a multimodal LLM session, not a dedicated transcription product). A separate, purpose-built streaming transcription model, "Gemini 3.5 Transcribe Live," is estimated (by third-party calculators, not an official flat per-minute rate) at a blended ~$0.009/min based on ~25 audio input tokens/sec + ~175 output tokens/min. — [Gemini API Pricing](https://ai.google.dev/gemini-api/docs/pricing) (official, referenced in search); blended-rate estimate: [WaveSpeed blog](https://wavespeed.ai/blog/cost-and-billing/gemini-3-5-transcribe-pricing/) (third-party, clearly labeled)

Real-time speaker diarization included free. ### Inferences
- OpenAI's and Gemini's transcription products are architected as LLM endpoints first and transcription APIs second; their "per-minute" prices are aggregator-computed conversions from token pricing, not a native per-minute SKU — this matters for cost predictability in a high-volume tutoring app where turn lengths vary.
- Deepgram, Soniox, AssemblyAI, and Speechmatics are the only providers in this set with pricing pages that explicitly separate "real-time/streaming" from "batch," each with real-time carrying a modest (Soniox, AssemblyAI ~20%) to large (Azure, AWS ~67-plus%) premium over batch — consistent with the operational cost of holding open low-latency sessions.
- Azure's "fast transcription" and Google's "dynamic batch" are both lower-cost tiers that should NOT be mistaken for real-time streaming when comparing quotes — a startup evaluating "cheap Azure/Google pricing" online may unknowingly be looking at the wrong SKU for a live conversational product.

### Gaps
- I was unable to independently confirm the live, rendered Azure and Google Cloud STT pricing tables first-hand in this session (both fetches returned masked/truncated content); the figures reported are corroborated by 2+ independent third-party aggregators each but are not primary-sourced the way Deepgram, Soniox, AssemblyAI, and AWS are in this report. A follow-up direct visit (with JS rendering) to azure.microsoft.com/pricing/details/speech and cloud.google.com/speech-to-text/pricing is recommended before finalizing a build vs. buy decision.
- No official volume-discount percentages were found for AWS Transcribe streaming beyond "additional volume discounts may be available" — exact tiers not public.
- Whisper API (`whisper-1`) is not natively a streaming endpoint (see next section); its $0.006/min price reflects batch/one-shot use, and OpenAI has not published a distinct "streaming Whisper" price.

## Which providers support true low-latency streaming (partial/interim transcripts), and what is their typical latency (time-to-first-partial, time-to-final)?

### Takeaway
Deepgram, AssemblyAI, Soniox, Speechmatics, Azure, and Amazon Transcribe all offer genuine bidirectional/WebSocket streaming with interim results; OpenAI's Whisper/gpt-4o-transcribe REST endpoints and Google's default Chirp 3 configuration are the weakest fits for a snappy live-conversation product unless specifically tuned — Google Chirp 3 in particular has a documented ~2.4-second latency issue on short utterances by default. Deepgram publishes the most specific hard latency numbers (first-word ~150ms, sub-300ms full streaming pipeline); AssemblyAI publishes a ~300ms turn-detection decision time built on top of its streaming transcripts.

### Cited Findings
- **Deepgram**: Streaming API delivers first-word latency near 150ms; Nova-3 model delivers sub-300ms streaming latency end-to-end. — [Deepgram: Streaming Speech Recognition API](https://deepgram.com/learn/streaming-speech-recognition-api) / [Measuring STT Latency docs](https://developers.deepgram.com/docs/measuring-streaming-latency)
- **AssemblyAI**: Universal-Streaming supports interim + final results over WebSocket; its neural end-of-turn detection (built on the streaming transcript stream) lands its "user has finished talking" decision in roughly 300ms, reading tonality/pacing rather than pure silence. — [AssemblyAI Turn Detection docs](https://www.assemblyai.com/docs/speech-to-text/universal-streaming/turn-detection); [AssemblyAI blog on turn detection](https://www.assemblyai.com/blog/turn-detection-endpointing-voice-agent)
- **Soniox**: Markets "low-latency audio streaming" infrastructure for real-time use cases (voice agents explicitly called out as a use case), but does not publish a specific millisecond time-to-first-partial or time-to-final figure on its public pricing/product pages. — [Soniox: Best STT for AI voice agents](https://soniox.com/speech-to-text/use-cases/voice-agents)
- **Google Cloud Speech-to-Text (Chirp 3)**: Supports StreamingRecognize with voice activity events, but by default waits for a pause after speech to finalize, causing ~2.4 seconds of latency on short utterances like "hi" or "yes" unless `VoiceActivityTimeout`/`speech_end_timeout` (min 500ms) is explicitly tuned down. This is a real, documented operational issue, not speculation. — [GitHub livekit/agents issue #4804](https://github.com/livekit/agents/issues/4804); [Google Cloud: Voice activity events and timeouts docs](https://docs.cloud.google.com/speech-to-text/docs/voice-activity-events)
- **Amazon Transcribe**: Offers a dedicated streaming API (distinct pricing SKU, see above) confirming real-time partial-transcript support exists, but no specific time-to-first-partial/time-to-final latency figure was found published by AWS in this research pass.
- **Azure**: Has a real-time transcription SKU (distinct from "fast transcription," which is batch/near-real-time) implying streaming/partial-result support, but no specific official latency-in-milliseconds figure was found in this pass.
- **OpenAI Whisper / gpt-4o-transcribe**: These are documented as request/response transcription endpoints priced per minute of submitted audio; nothing found in this pass indicates a persistent low-latency partial-transcript streaming mode comparable to Deepgram/AssemblyAI/Soniox for these specific model names (OpenAI's real-time audio conversation capability instead lives in the separate Realtime API / "GPT Realtime" line, which appeared in AssemblyAI's own benchmark table as a distinct entry — see next section).

### Inferences
- For a live voice-tutoring product, Deepgram and AssemblyAI currently have the most operationally-transparent, sub-second latency stories with specific published numbers; Soniox likely performs comparably given its architecture and marketing claims but a startup should benchmark it directly rather than rely on published figures.
- Google's Chirp 3 default configuration is a latency trap for conversational use and would need explicit endpoint tuning (`voice_activity_timeout`) to be viable — out of the box it is not a good fit for a snappy tutor.

### Gaps
- No official numeric time-to-first-partial or time-to-final latency figures were found for Soniox, Azure Speech, or Amazon Transcribe streaming — flagged as a gap rather than estimated.
- No independent (non-vendor) latency benchmark comparing all providers side-by-side under identical network/hardware conditions was found in this pass; all latency claims above are vendor-published or from third-party developer bug reports (Google case), not a controlled bake-off.

## How good is each provider at German-language transcription specifically — published WER benchmarks or credible third-party comparisons?

### Takeaway
German-specific WER figures exist for most major providers, but they come from vendor-run (often self-serving) benchmarks using different test sets (FLEURS, Common Voice, YouTube audio, internal production data) and dates, so cross-provider comparison must be treated cautiously — every vendor's own benchmark shows that vendor winning. That said, multiple independent-ish benchmarks converge on Soniox, AssemblyAI (Universal-3.5), Deepgram (Nova-3), and Speechmatics as the strongest German performers, generally landing German WER in the mid-single-digit-to-~9% range, while Azure, AWS, Google, and OpenAI's general-purpose/realtime models trend toward the higher single digits to low double digits.

### Cited Findings
- **AssemblyAI's own published benchmark suite** (run 2026-08-25 → 2026-09-03, FLEURS dataset, "parallel sentences read by native speakers in quiet settings"): German WER — AssemblyAI Universal-3.5 Pro 5.3%, ElevenLabs Scribe v2 5.8%, Speechmatics Enhanced 6.8%, Mistral Voxtral Mini 7.8%, AWS Transcribe 8.0%, Azure 9.1%, OpenAI GPT Realtime 11.2%. On Mozilla Common Voice German, AssemblyAI reports 5.0% WER for itself. — [AssemblyAI Benchmarks](https://www.assemblyai.com/benchmarks) (official, fetched directly). **This is a vendor-published benchmark where AssemblyAI is the tested vendor** — treat the AssemblyAI-wins-every-category framing with appropriate skepticism, though the relative ordering and other vendors' numbers may still be informative since AssemblyAI would have less incentive to inflate competitors' scores upward. Note: Google, Deepgram, and Soniox are conspicuously absent from AssemblyAI's own comparison table.
- **Deepgram's own published benchmark**: On 26 hours of real German production/curated audio (200,000+ words), Nova-3 Multi achieved 8.8% WER on pre-recorded (batch) German audio, which Deepgram states is #1 among competitors tested with a 29% relative WER reduction vs. the next-best competitor; German streaming showed up to 11.4% relative WER reduction vs. Deepgram's own prior model (Nova-2), not vs. competitors. — [Deepgram: German Benchmarks](https://deepgram.com/learn/german-benchmarks) (vendor-published; competitor identities and exact competitor WER numbers were not surfaced in this pass — only Deepgram's relative-improvement framing).
- **Soniox's own published benchmarks**: A cited 2025 study across 60 languages using real-world YouTube audio reportedly showed Soniox at 7% WER for German vs. Google 16.1%, OpenAI 10.4%, Azure 10.8%. A separate, seemingly more recent claim cites Soniox at "1.25% WER for German" beating Speechmatics/Cartesia/AWS — this 1.25% figure looks like an outlier/likely a different (easier, cleaner-audio) test condition than the 7% figure, and both are vendor-published comparison pages (soniox.com/compare/*), so should be treated as directionally suggestive rather than authoritative. An earlier March 2023 Soniox-published benchmark showed Soniox 5.92% average WER vs. Speechmatics 8.56% and Azure 9.41% (language/scope not fully specified as German-only in the snippet). — [Soniox vs Google German page](https://soniox.com/compare/soniox-vs-google/german); [Soniox 2023 German benchmark PDF](https://soniox.com/media/SonioxGermanBenchmarks2023.pdf) — dated 2023, explicitly older than the 2026 constraint, flagged accordingly.
- **General-purpose open benchmark context**: Whisper Large V3 is described as the multilingual "gold standard" (99+ languages, 1.55B params) with ~7.4% WER on mixed/average benchmarks (not German-specific). — [Northflank: Best open source STT 2026](https://northflank.com/blog/best-open-source-speech-to-text-stt-model-in-2026-benchmarks) (third-party, aggregate/mixed-language number, not German-specific)
- **Academic/dialect-specific note**: A 2026 arXiv paper on Swiss German ASR found even a fine-tuned Whisper reaching only 25.6% WER (13.8% content-WER) on Swiss German dialect audio — a reminder that all the vendor numbers above are almost certainly measured on Standard High German, and performance would likely degrade substantially on dialectal/regional German speech (relevant if the tutoring app's users include Swiss/Austrian or strongly dialectal speakers). — [arXiv 2606.07608](https://arxiv.org/html/2606.07608v1) (independent academic source, most credible/least vendor-biased finding in this section)
- **Gemini 3.5 Transcribe**: Google's own material claims an average WER of 4.0% for streaming and 2.6% for non-streaming transcription across 85+ supported languages — this is a blended multilingual average, not German-specific, and is vendor-published. — [Google/daily.dev: Gemini 3.8 Live and 3.5 Transcribe](https://daily.dev/posts/build-real-time-voice-applications-with-gemini-3-8-live-and-3-5-transcribe-8ssfol3mo) (third-party republishing of Google's announcement, not independently verified)

### Inferences
- No single neutral, independently-run, multi-provider German WER leaderboard was found; every German-specific number in this research comes from a vendor benchmarking itself (or a vendor's comparison page benchmarking a competitor, which carries its own bias risk toward making the vendor look good). A startup serious about this decision should run its own held-out German audio (ideally actual target-user accents/dialects, plus classroom/tutoring-style speech with disfluencies) through candidate APIs before committing.
- Directionally, across multiple independent vendor benchmarks, Soniox, AssemblyAI (Universal-3.5), Speechmatics, and Deepgram (Nova-3) repeatedly appear as leaders on German, while Google Cloud STT and OpenAI's general realtime/transcribe models repeatedly appear as relative laggards on German WER — this pattern recurring across benchmarks from different, unaffiliated vendors improves (but does not confirm) its credibility.
- Standard High German performance figures should not be assumed to transfer to Austrian German, Swiss German, or heavily accented/dialectal learner speech — relevant since this is a tutoring product likely serving non-native speakers with varied accents, which is arguably an even harder condition than any benchmark cited here (all benchmarks use native-speaker or clean production audio).

### Gaps
- No credible, non-vendor, third-party German WER leaderboard covering all seven target providers under one consistent methodology was found — this is stated explicitly rather than guessed at, per the research brief's constraint.
- No German WER figure specific to accented/non-native or classroom-dialogue speech (the actual use case for a language-tutoring app) was found for any provider — all published numbers use native-speaker or general production/media audio.
- Soniox's two conflicting self-published German WER figures (7% vs. 1.25%) could not be reconciled in this pass (different test sets/dates likely, but the exact methodology difference was not confirmed).

## Do any of these offer built-in Voice Activity Detection (VAD) or turn/end-of-speech detection, or is it always a separate component?

### Takeaway
Built-in VAD/endpointing is common (Deepgram, Google, and implicitly Azure/AWS via their streaming APIs), but true semantic "turn detection" (distinguishing a mid-sentence pause from an actual end-of-turn) beyond simple silence-timers is a more advanced, less universal feature — Deepgram and AssemblyAI both explicitly ship it as part of their product, with AssemblyAI marketing its version as neural/tonality-aware rather than silence-only.

### Cited Findings
- **Deepgram**: Ships built-in Endpointing (VAD-based, default 10ms silence trigger, configurable) and a separate "UtteranceEnd" feature (>1 second gap detection using interim/final transcript analysis) explicitly for end-of-speech detection in live streaming. Deepgram's own docs note VAD can be confused by background noise (music, ringing phones, drive-thru noise). — [Deepgram: End of Speech Detection docs](https://developers.deepgram.com/docs/understanding-end-of-speech-detection); [Deepgram: Endpointing docs](https://developers.deepgram.com/docs/endpointing); [Deepgram: Utterance End docs](https://developers.deepgram.com/docs/utterance-end)
- **AssemblyAI**: Its Voice Agent API uses "neural end-of-turn detection instead of traditional silence-based methods" — reads tonality and pacing and lands a decision in ~300ms; turn detection and barge-in support are on by default with `end_of_turn: true`, requiring no separate VAD component to be wired up by the developer. AssemblyAI explicitly frames traditional VAD/silence-timer approaches as inferior ("the agent barges in... conversation falls apart") to its own approach. — [AssemblyAI Turn Detection docs](https://www.assemblyai.com/docs/speech-to-text/universal-streaming/turn-detection); [AssemblyAI: Turn detection blog](https://www.assemblyai.com/blog/turn-detection-endpointing-voice-agent)
- **Google Cloud Speech-to-Text V2**: Supports `enable_voice_activity_events` for real-time speech-start/speech-end events during streaming, plus `StreamingRecognitionFeatures.VoiceActivityTimeout` (`speech_start_timeout`, `speech_end_timeout`, configurable 500ms–60s) to tune endpointing sensitivity — this is a built-in, official feature, though the default configuration is tuned for accuracy over latency (see the ~2.4s latency finding above). — [Google Cloud: Voice activity events and timeouts docs](https://docs.cloud.google.com/speech-to-text/docs/voice-activity-events)
- **Soniox**: Markets itself for voice-agent use cases but no explicit VAD/endpointing feature documentation was surfaced in this research pass — presence/absence could not be confirmed either way from the pages fetched.
- **Azure / Amazon Transcribe**: Both offer real-time streaming APIs implying some level of built-in segmentation, but no specific official VAD/turn-detection feature documentation was surfaced for either in this pass (this is a genuine gap, not a confirmed "no").

### Inferences
- For a conversational tutoring app, AssemblyAI's and Deepgram's built-in turn-detection primitives likely reduce the amount of custom VAD/interruption-handling logic the startup would otherwise need to build, compared to providers where this wasn't confirmed as a first-class feature.
- "VAD" and "turn detection" are not synonyms in this space: VAD (as in Deepgram's default Endpointing and Google's voice-activity-events) is a lower-level acoustic silence detector, while AssemblyAI's neural end-of-turn detection is a higher-level, semantically-aware layer built on top of the transcript stream — a startup should be clear about which layer they need (or need both).

### Gaps
- No official documentation confirming or ruling out built-in VAD/turn-detection was found for Soniox, Azure Speech, or Amazon Transcribe in this pass — flagged explicitly rather than assumed either way.
- Whether any provider's turn detection has been evaluated specifically for German speech patterns/prosody (turn-taking cues can be language-specific) was not found anywhere in this research — a real open question for the German-tutor use case.

## Rough cost per hour of continuous audio transcription for the top 3-4 realistic real-time candidates

### Takeaway
Among providers with confirmed, official, real-time-specific pricing, Deepgram is the cheapest realistic streaming candidate (~$0.29–0.35/hr PAYG depending on mono/multilingual), followed closely by Soniox (~$0.12/hr) and AssemblyAI (~$0.15–0.45/hr depending on tier) as the next tier, with Speechmatics (~$0.40/hr Pro) and Amazon Transcribe ($0.60/hr, officially confirmed) as mid-tier, and Azure (~$1.00/hr, aggregator-sourced) and Google Cloud STT (~$0.96/hr at $0.016/min, aggregator-sourced) as the most expensive of the group for true real-time streaming.

### Cited Findings (computed from official/near-official per-minute or per-hour figures cited above)
- **Deepgram Nova-3 Monolingual streaming, PAYG**: $0.0048/min × 60 = **$0.288/hour**. Multilingual: $0.0058/min × 60 = **$0.348/hour**. — computed from [Deepgram Pricing](https://deepgram.com/pricing)
- **Soniox real-time streaming**: officially quoted directly as **$0.12/hour**. — [Soniox Pricing](https://soniox.com/pricing)
- **AssemblyAI Universal-Streaming (incl. German multilingual)**: officially quoted directly as **$0.15/hour** base (Universal-3.5 Pro Realtime: **$0.45/hour**). — [AssemblyAI Pricing](https://www.assemblyai.com/pricing)
- **Speechmatics real-time, Pro tier**: $0.0067/min × 60 = **~$0.40/hour** (secondary-sourced, not directly fetched from speechmatics.com/pricing in this pass).
- **Amazon Transcribe streaming**: officially confirmed $0.01/min × 60 = **$0.60/hour** (directly fetched from AWS's own pricing page).
- **Azure Speech real-time standard**: aggregator-reported **~$1.00/hour** (~$0.0167/min) — not confirmed first-hand against the live official price table in this session (see caveats above).
- **Google Cloud Speech-to-Text V2 standard streaming**: aggregator-reported $0.016/min × 60 = **~$0.96/hour** — likewise not confirmed first-hand against the live official price table in this session.
- **OpenAI gpt-4o-transcribe / whisper-1**: $0.006/min × 60 = **$0.36/hour** — but caveat this is a batch/one-shot transcription endpoint price, not confirmed as a true persistent low-latency streaming session price (see latency section).

### Inferences
- For a cost-sensitive startup building a real-time German tutoring product, the three most realistic candidates purely on a $/hour basis with genuine streaming support and at least some German-specific accuracy evidence are **Soniox (~$0.12/hr), Deepgram (~$0.29–0.35/hr), and AssemblyAI (~$0.15–0.45/hr)** — all three are also among the strongest German WER performers cited above, which is a favorable coincidence (cheapest ≠ worst accuracy here, based on available vendor-published numbers).
- Amazon Transcribe (~$0.60/hr) is a reasonable "safe/enterprise" fallback with official, directly-confirmed pricing and native AWS ecosystem integration, but costs roughly 2-5x the cheapest options above.
- Azure and Google, at an estimated ~$0.96–1.00/hr, are the least cost-competitive of the group for pure real-time streaming STT specifically (independent of their broader cloud-ecosystem advantages), and also scored weaker on the one cross-vendor German WER table found (AssemblyAI's FLEURS benchmark: Azure 9.1% WER vs. AssemblyAI's own 5.3%).

### Gaps
- These are all "list/PAYG" rates; none of the volume-discount tiers (Deepgram Growth, AssemblyAI committed plans, Speechmatics Enterprise, AWS/Azure/Google committed-use discounts) were fully quantified with exact percentages/thresholds beyond what's cited above, so real production costs at scale could shift the ranking.
- None of these hourly figures include the cost of a separate LLM (for the tutoring "brain") or TTS (for spoken responses) — this is STT cost only, one leg of a three-part real-time voice pipeline (STT → LLM → TTS), each of which has its own per-minute cost that would need to be added for a true "cost per hour of tutoring session" figure.
