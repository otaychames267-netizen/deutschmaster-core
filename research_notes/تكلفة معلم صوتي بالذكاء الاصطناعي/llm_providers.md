## Realtime speech-to-speech API pricing and capabilities (OpenAI, Google, others)

### Takeaway
OpenAI's Realtime API (`gpt-realtime-2.1`) and Google's Gemini Live API (`Gemini 3.8 Live`) are the two primary native-audio speech-to-speech offerings; both price audio as expensive per-token audio (not flat per-minute), and OpenAI's realtime audio is roughly 3–8x more expensive per minute than Google's Live API in the figures found. True end-to-end speech-to-speech from other providers is rare — most "other" realtime voice providers (Inworld, Deepgram, AssemblyAI, Gladia, ElevenLabs) are cascaded (STT→LLM→TTS) under the hood, not single-model native audio-to-audio.

### Cited Findings
- **OpenAI Realtime API** (from `developers.openai.com/api/docs/pricing`, the OpenAI docs pricing page): powered by `gpt-realtime-2.1`. Audio input — $32.00/1M tokens ($0.40/1M cached audio input). Audio output — $64.00/1M tokens. Text input — $4.00/1M tokens ($0.40/1M cached). Text output — $24.00/1M tokens. There is also a smaller "mini" realtime model reported (third-party) at roughly $10/1M audio input and $20/1M audio output tokens. — [OpenAI Pricing docs](https://developers.openai.com/api/docs/pricing)
- Converting OpenAI's realtime audio token pricing to per-minute costs, third-party analysis puts full `gpt-realtime-2.1` at roughly $0.05–$0.32/minute depending on context growth/caching assumptions (one estimate: ~$0.091/min "computed" cost; another: $0.32/min uncached vs. $0.075/min with caching and trimmed tool schemas), and the mini variant at roughly $0.016–$0.12/min. Estimates vary substantially by source because "per minute" isn't officially how OpenAI bills — it bills per audio token, and actual tokens/minute depends on audio encoding and conversational back-and-forth patterns. — [TokenMix realtime voice cost analysis](https://tokenmix.ai/blog/openai-realtime-voice-api-2026-cost-latency), [Layer3Labs realtime pricing guide](https://www.layer3labs.io/guides/openai-realtime-api-pricing)
- OpenAI also offers `gpt-realtime-translate` at a reported $0.034/minute and Whisper (STT-only, not speech-to-speech) at a reported $0.017/minute — these are cascaded-adjacent, cheaper alternatives to full realtime dialog. — [TokenCost OpenAI voice pricing](https://tokencost.app/blog/openai-gpt-realtime-2-voice-pricing)
- Direct fetch of `openai.com/api/pricing/` (the primary marketing page, which normally has a dedicated Realtime API section) returned HTTP 403 in this session — the realtime figures above come from the `developers.openai.com` docs mirror and third-party analyses, not the primary marketing/pricing page directly.
- **Google Gemini Live API** (fetched from `ai.google.dev/gemini-api/docs/pricing`): Gemini 3.8 Live — audio input $3.00/1M tokens (≈$0.005/minute); audio output $12.00/1M tokens (≈$0.018/minute). A related "Gemini 3.5 Live Translate" model is priced higher: $3.50/1M input (≈$0.0053/min), $21.00/1M output (≈$0.0315/min). Google's per-minute conversion assumes roughly 25 audio tokens per second. — [Gemini API Pricing](https://ai.google.dev/gemini-api/docs/pricing)
- A search-based cross-check corroborates the $3/$12 per-1M-token and $0.005/$0.018-per-minute figures for Gemini 3.8 Live, and separately cites an older/different SKU "Gemini 2.5 Flash Live" at $0.01125/minute combined, supporting "30 HD voices in 24 languages." — [Ry Walker Gemini Live API research](https://rywalker.com/research/gemini-live-api), [Inworld voice-agent cost model](https://inworld.ai/resources/voice-agent-cost-per-minute-2026)
- **Other realtime speech-to-speech options**: Inworld AI offers a "Realtime API" but it is explicitly a model-agnostic router (STT + its own "Realtime TTS-2"/"Realtime TTS-2 Flash" + an LLM chosen from 220+ models) — i.e., cascaded, not a single native audio-to-audio model. AssemblyAI's Universal-3.5 Pro Realtime is STT-only, priced around $0.45/hr base with three latency modes. Deepgram (Flux) and Gladia (Solaria-1) both advertise sub-300ms STT latency but are also STT-only, not full speech-to-speech. No other provider researched offers a genuine single-model native audio-in/audio-out API comparable to OpenAI Realtime or Gemini Live. — [Inworld: best speech-to-speech APIs 2026](https://inworld.ai/resources/best-speech-to-speech-apis), [Inworld: best speech-to-speech](https://inworld.ai/resources/best-speech-to-speech)

### Inferences
- For a German-tutoring voice product, OpenAI's and Google's native speech-to-speech APIs are the only two credible "true" realtime speech-to-speech options as of this research; every other "realtime voice API" found in this search is a cascaded pipeline marketed as realtime, meaning the buy vs. build distinction for a voice tutor is really "OpenAI Realtime vs. Gemini Live vs. build-your-own cascade," not a wider market of native S2S vendors.
- Gemini Live's audio pricing (~$0.005/min in + $0.018/min out ≈ $0.023/min combined at steady talk) is roughly 4–14x cheaper per minute than the various OpenAI Realtime per-minute estimates found ($0.075–$0.32/min for the flagship-class realtime model), making Gemini Live the stronger default for a cost-sensitive, high-conversation-volume tutoring product, assuming its German audio quality and Live API feature set (interruption handling, turn-taking) are adequate — this was not independently verified for German specifically in this pass.

### Gaps
- Could not fetch OpenAI's primary marketing pricing page directly (403), so the Realtime API figures rely on a docs-subdomain mirror plus third-party per-minute conversions that disagree with each other by roughly 4x depending on caching/context assumptions — an exact "$/hour of continuous German conversation" figure for OpenAI Realtime should be treated as a range, not a point estimate, until validated with real usage logs.

## Fastest providers for low-latency conversational use (Groq, Cerebras throughput)

### Takeaway
Cerebras' wafer-scale hardware posts higher raw tokens/sec than Groq's LPUs on comparable model sizes (e.g., ~1,800–2,600 tok/s on 8B–32B-class open models vs. Groq's ~280–1,000 tok/s range), but both are far faster than typical GPU-based flagship-model serving, and Artificial Analysis independently confirmed Groq as the fastest benchmarked provider for Llama 3.3 70B specifically.
### Cited Findings
- **Groq**: Llama 3.1 8B Instant achieves 560–840 tokens/sec; Llama 3.3 70B achieves 280–394 tokens/sec on Groq's own reporting. Independent benchmarking firm Artificial Analysis measured Groq serving Llama 3.3 70B at 276 tokens/second, calling it "the fastest of all benchmarked providers" for that specific model. General range cited: 280–1,000 tokens/sec across Groq's open-model lineup, described as "typically 10-20x cheaper than equivalent OpenAI models." — [Artificial Analysis: Groq provider page](https://artificialanalysis.ai/providers/groq), [eesel Groq pricing/speed summary](https://www.eesel.ai/blog/groq-pricing)
- **Cerebras**: Llama 3.1 8B — ~1,800 tokens/sec; Llama 3.1 70B — ~450 tokens/sec; Llama 4 Maverick 400B — ~2,522 tokens/sec; Qwen 3 32B — ~2,600 tokens/sec; Qwen3 235B Instruct — ~1,400 tokens/sec; a newer "Qwen 3.8 27B" addition to Cerebras' public tier is cited at ~1,500 tokens/sec. One third-party benchmark separately reports ~2,600 tokens/sec on "Llama4Scout." — [explainx.ai Cerebras Qwen benchmark writeup](https://explainx.ai/blog/cerebras-qwen3-8-27b-1500-tokens-per-second-2026), [Adam Holter Cerebras free-tier speed benchmarks](https://adam.holter.com/cerebras-opens-a-free-1m-tokens-per-day-inference-tier-and-ccerebras-now-offers-free-inference-with-1m-tokens-per-day-real-speed-benchmarks-show-2600-tokens-sec-on-llama4scout-here-are-the-actual-n/)

### Inferences
- For the "casual real-time conversational tutoring" half of the product, both Groq and Cerebras' open-weight-model throughput (hundreds to low-thousands of tokens/sec) is almost certainly fast enough that model inference speed would not be the bottleneck compared to audio I/O (STT/TTS) latency in a cascaded pipeline — meaning the choice between Groq and Cerebras for this use case likely comes down to price and specific model availability (Groq offers a broader open-model menu including Kimi K2 and Llama variants; Cerebras' public serverless tier is currently narrower, centered on GPT-OSS-120B).

### Gaps

## OpenRouter's latency/cost overhead and value proposition for a production voice app

### Takeaway
OpenRouter does not mark up per-token model pricing (same price as calling the provider directly) but does charge fees on credit top-ups (5.5% card / 5% crypto) and on BYOK usage above a free allotment (5%), and adds a reported 25–40ms of routing latency — its core value for a production app is unified billing, automatic provider failover, and access to many models behind one API key, not cost savings on tokens themselves.

### Cited Findings
- "OpenRouter doesn't mark up per-token model prices — the same model costs the same per token whether you call the provider directly or route through OpenRouter." — [TrueFoundry: OpenRouter Pricing 2026](https://www.truefoundry.com/blog/openrouter-pricing)
- OpenRouter charges a 5.5% fee on credit-card credit top-ups (5% for crypto) with an $0.80 minimum per transaction; BYOK (bring-your-own-key) usage gets a monthly free allotment of list-price inference, after which a 5% fee applies. — [OpenRouter FAQ](https://openrouter.ai/docs/faq)
- Reported routing/latency overhead: "OpenRouter adds 25-40ms latency overhead," though its fallback routing "can reduce application-level delays when a provider is throttled or unavailable" — i.e., a small fixed latency tax that can be offset in aggregate by avoiding provider outages/throttling. — [CallMissed: OpenRouter vs Direct Provider APIs 2026](https://www.callmissed.com/blog/openrouter-vs-direct-provider-apis-2026-pricing)
- Routing variants: `:nitro` sorts providers by throughput (fastest first), `:floor` sorts by price (cheapest first), `:exacto` sorts by quality signals tuned for tool-calling reliability — giving a developer explicit control over the speed/cost/quality trade-off per request without changing application code. — [datastudios.org: OpenRouter routing/failover/latency](https://www.datastudios.org/post/openrouter-model-routing-provider-failover-latency-and-cost-optimization)
- Value proposition summarized by a third-party review: "one API key, unified billing, automatic failover... and access to models you might not have individual API keys for," useful for "testing a panel of expert models... without changing application code," and best suited to teams that "value provider flexibility more than private deployment or deep governance." — [betterclaw.io: OpenRouter vs Direct API](https://www.betterclaw.io/blog/openrouter-vs-direct-api-agents)

### Inferences
- For a real-time voice tutoring product where every added millisecond of latency is user-perceptible, OpenRouter's 25–40ms overhead is likely negligible next to audio encode/decode and network round-trip time, but it only routes text-completion calls — it does not appear to offer realtime speech-to-speech routing (no evidence found of OpenRouter proxying OpenAI Realtime or Gemini Live sessions), so its value would be limited to the cascaded-pipeline text/grammar-evaluation leg of the product, not the live conversational audio leg.
- Given no token markup and only fee exposure on top-ups/BYOK overage, OpenRouter is best framed as an operational-resilience and multi-model-flexibility layer (useful if the product wants to A/B test or fall back between GPT-5, Gemini, Grok, or open models for the "careful grammar correction" task) rather than a cost-saving mechanism.

### Gaps
- Direct fetch of `openrouter.ai/docs/pricing` returned HTTP 404 in this session — the pricing/fee figures above rely on the OpenRouter FAQ page (which did load) and third-party reviews, not a single canonical current pricing page.
- No data found on whether OpenRouter offers any realtime/audio-native routing at all (as opposed to purely text-completion routing) — should be confirmed directly with OpenRouter if a unified realtime-plus-text routing layer is desired.

## Cost per hour of continuous conversation: realtime speech-to-speech vs. cascaded text-LLM approach

### Takeaway
Third-party cost modeling puts cascaded (STT→LLM→TTS) voice pipelines at roughly $0.007–$0.17 per conversation-minute (commonly cited around $0.13/min "in production"), while native realtime speech-to-speech models run roughly 10x more expensive per minute due to audio-token-based billing and context re-accumulation each turn — meaning a full hour of continuous back-and-forth could cost very roughly $0.40–$10+ depending on architecture and specific models chosen, a wide range that should be narrowed with real usage testing rather than treated as precise.

### Cited Findings
- "Cascaded stacks cost approximately $0.007 to $0.029 per conversation minute" in one estimate, while "in production, a cascaded voice stack runs about $0.13/minute" in another — a roughly 4–20x spread depending on model/voice choices within the cascaded category itself. TTS is reported to dominate cascaded-stack cost at "70 to 73 percent of raw component cost at 400 characters per conversation minute," with "agent speech costs roughly $0.02 per spoken minute on TTS-2, before the LLM." — [Inworld: Voice Agent Cost Per Minute 2026](https://inworld.ai/resources/voice-agent-cost-per-minute-2026)
- Realtime (native speech-to-speech) cost estimates found: "gpt-realtime-2.1 computes to roughly $0.091 per conversation minute" in one source; another cites "native realtime uncached runs about $0.32/minute, and the same realtime call with caching and trimmed tool schemas runs about $0.075/minute." Gemini's "2.5 Flash Live" is cited separately at "$0.01125/min" combined. — [TokenMix realtime cost/latency analysis](https://tokenmix.ai/blog/openai-realtime-voice-api-2026-cost-latency), [Inworld: Voice Agent Cost Per Minute 2026](https://inworld.ai/resources/voice-agent-cost-per-minute-2026)
- "Speech-to-speech models run approximately 10 times the cost of chained pipelines, largely due to context accumulation where the model re-charges for all previous tokens on each turn." A cascaded pipeline's cost is described as consistent/linear regardless of conversation length ("a 10-minute call costs exactly 10x a 1-minute call"), whereas realtime S2S costs are described as far more variable ("S2S costs range 182x" across scenarios in the source's own modeling). — [Inworld: Cascaded vs Speech-to-Speech Voice Architecture](https://inworld.ai/resources/cascaded-vs-speech-to-speech-voice-architecture)
- Trade-off noted: "S2S achieves an 85% latency reduction over non-streaming cascaded pipelines," and "as of 2026, cascaded dominates enterprise deployments because of debuggability, compliance, and provider flexibility" despite realtime S2S's latency advantage. — [Inworld: Cascaded vs Speech-to-Speech Voice Architecture](https://inworld.ai/resources/cascaded-vs-speech-to-speech-voice-architecture)
- Component-level cascaded costs found separately in this research that can be used to sanity-check the above: Groq Whisper Large v3 Turbo STT — $0.04/hour of audio (with a 10-second-minimum billing granularity per request); PlayAI Dialog v1.0 TTS on Groq — $50/1M characters. At ~150 words/minute spoken (roughly 800–900 characters/minute of German text, accounting for longer average German word length), TTS alone on this specific stack would run in the very rough range of $0.04–$0.05 per spoken minute for the AI's output — broadly consistent with the "$0.02–$0.03/min TTS-dominated" figures cited above once the LLM and STT legs are added. — [Groq Whisper pricing (via search)](https://console.groq.com/docs/model/whisper-large-v3-turbo), [Inworld: Voice Agent Cost Per Minute 2026](https://inworld.ai/resources/voice-agent-cost-per-minute-2026)

### Inferences
- Extrapolating the per-minute figures found to a full hour of continuous back-and-forth conversation (assuming roughly continuous speech from both sides, per the assignment's stated assumption): a cascaded pipeline built on cost-efficient components (e.g., Groq/Cerebras for the LLM leg, Groq Whisper for STT, a mid-tier TTS) would very roughly land somewhere in the $0.40–$8/hour range depending on model/voice tier chosen (using the $0.007–$0.13/min range found, ×60 minutes); a native realtime speech-to-speech hour (OpenAI Realtime at the higher-end $0.075–$0.32/min figures found, ×60) would very roughly land in the $4.50–$19/hour range, while Gemini Live's much lower per-minute figures ($0.005 in + $0.018 out ≈ $0.023/min combined, ×60) would land around $1.40/hour — making Gemini Live's realtime API potentially cost-competitive with, or even cheaper than, a naively-built cascaded stack, if its German audio quality holds up in practice.
- Given the 10x-cost and highly variable ("182x range") nature of realtime S2S cost reported by one source, and the fact that OpenAI Realtime specifically shows the widest cost variance in the figures found, a cascaded architecture (using a fast/cheap LLM like Groq- or Cerebras-hosted Llama/Qwen for casual conversational turns, with a flagship model reserved for grading) likely gives more predictable unit economics for a product that needs to forecast per-user cost at scale — Gemini Live is the one native-S2S option whose figures suggest it could compete with cascaded costs, and is worth prototyping directly rather than assuming cascaded is always cheaper.

### Gaps
- None of the cost-per-minute figures found were computed specifically for German-language conversation (word/character density, and thus TTS character-billing and audio-token counts, differ between English and German) — the ~150-words/minute assumption in the assignment should be re-modeled with actual German TTS character counts and actual German audio-token consumption rates (Google's ~25-tokens/second-of-audio conversion factor is the only concrete audio-token-rate figure found, and it wasn't confirmed as English-vs-German-invariant).
- All "cost per hour" figures in this section are derived by linearly extrapolating third-party per-minute estimates, not measured directly for an hour-long session or reported by any of the providers themselves — this should be validated with a real pilot conversation (e.g., a 10-minute test call against both OpenAI Realtime and Gemini Live with actual German audio) before being used for financial planning.
- No cascaded-pipeline cost figures were found for a German-specific TTS voice (voice/language selection can materially change TTS per-character or per-minute pricing on some providers) — should be checked against the specific TTS vendor and German voice model chosen.
